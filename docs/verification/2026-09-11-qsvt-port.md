# QSP/QSVT port and Astro Float verification — 2026-09-11

The C++ reference is `quest-qsvt` revision
`7fe7f740579b03c52a8cf48be6a31268b029c19f`. This record covers numerical,
native and certification checks for the port using `astro-float 0.9.6`
(`astro-float-num 0.3.7`), which replaced Rug/GMP/MPFR.
The later [documentation and integration checks](2026-09-11-qsp-qsvt-documentation.md)
are recorded separately, preserving the measurements below.

## Interface coverage

Six crates provide numerical workspaces, typed polynomial bases/function
expressions, canonical and generalized QSP, projected QSVT models, interchange,
and applications. Consuming builders separate admission, completion, frozen
controls, certification, transform construction and native preparation.

Production synthesis uses binary64, RustFFT and explicit caller-owned Rayon
pools; dense operations use faer with `Par::Seq`. Certification and the explicit
offline solver use optional Astro Float. A failed binary64 request cannot select
the offline solver. Native preparation and repeated execution contain no
arbitrary-precision arithmetic. Source-boundary regressions and a build without
the optional dependency cover this separation; the removed GMP allocator-hook
test is historical evidence, not an Astro allocator measurement.

Shared immutable oracle bodies retain invocation identity, phase and operand
order. The macro supports Rust `oracle` captures and numerical `adjoint @`, with
exact-only `inv @`. Projected transforms remain distinct from coherent oracles.
All seven QSVT routes, rectangular encodings, coordinates/dense/isometry
projectors, consuming conditioning and complex Hadamard observations are
implemented. `admit()` and `prepare()` separate Rust lowering/budget ownership
from native allocation. Owned snapshots survive native runtime retirement.

The application exposes synthesis, explicit offline synthesis, all 21 inverse
catalog families, embedded transforms, physical solve and overlap workflows.
JSON and serial HDF5 preserve complex data, sparse duplicate order, padding and
normalization. Distributed embedded/overlap use root-only IO/synthesis and
frozen broadcasts. rsmpi owns `MPI_THREAD_MULTIPLE`; API availability requires
both Cargo `mpi` and an MPI/SUBCOMM-enabled QuEST target. `--workers auto` resolves
local parallelism; distributed workers start on the subgroup root only, after
thread-support admission. Pool failure is agreed before native execution.

Native dispatch reports count the fixed successful per-rank schedule,
including decompositions, signed-control toggles, projection and readout calls.
They distinguish semantic queries and oriented source applications. They do not
count setup, fingerprint/lifecycle checks, MPI agreement, caller snapshots,
later conditioning or a partially failed dispatch.

## Mathematical and numerical evidence

All **43 catalog cases** established every requested bound at **256 bits, first
attempt**, with the unchanged `1e-11` tolerances: 21 canonical, 21 generalized,
and one complex rotation of the degree-8,105 target. These verify the actual
frozen binary64 exports, including every matrix-polynomial entry and scalar
phase. Separate response, completion, conversion, reconstruction and unitarity
summaries are retained in [the machine-readable summary](data/2026-09-11-qsvt/astro-catalog-summary.json)
and its two detailed JSONL files.

| Degree 8,105 case | Response upper bound | Reconstruction upper bound |
| --- | ---: | ---: |
| Canonical | 2.279e-15 | 5.335e-15 |
| Generalized, real target | 1.675e-14 | 3.807e-14 |
| Generalized, complex target | 6.325e-15 | 1.418e-14 |

The explicit offline degree-8,105 solver also succeeded at 128 bits and its
binary64 export certified independently at 256 bits. Its response upper bound
was below `4.200e-17`. The final release scale run passed all three deliberately
separate tests: analytic degree 8,192, offline degree 8,105, and deterministic
1/2/4-worker canonical/generalized degree-8,105 exports with certification.

Astro's upstream `from_f64` incorrectly halves subnormal inputs in the pinned
release. The project adapter uses integer bit decoding instead. Independent raw
integer-dyadic fixtures cover seeded inputs, signed zeros, underflow, overflow,
halfway neighbors and distant sticky bits. Certification uses directed primitive
operations, exact integer octant reduction for twiddles and checked endpoint
errors; it does not use Astro's expression macro. Acceptance compares original
multiprecision bounds before outward binary64 conversion. Correctness relies on
the backend's primitive directed-rounding contracts; tests also retain direct
convolution and independent scalar/integer references.

An extreme-phase regression covers a separate defect: adding convention offsets
directly to phases such as `1e20` or `f64::MAX` can lose the offset. Conversion now
composes the actual rotation and uses bounded `atan2` when needed, preserving
ordinary phase bits. Its accumulated roundoff estimate remains a numerical
diagnostic, not a certificate. Full complex QSP/QSVT fixtures exercise both signs
of these extreme inputs.

Standard QSVT theorem reports are conditional on explicit mathematical premises
attached to the same transform. Empirical matrix admission, sampled residuals and
phase-conversion estimates do not become theorem premises automatically.
Generalized theorem-level robustness remains uncertified; its QSP/control
certificates and numerical observations are reported separately.

## Local verification

The host was Linux x86_64, AMD Ryzen 9 7950X (32 logical CPUs), pinned
`nightly-2026-09-06`, GCC 16.1.1 and QuEST 4.3.0. The installed package includes
CUDA/cuQuantum, OpenMP, MPI and SUBCOMM, with binary64 and deprecated APIs off.
Execution tests used CPU/local MPICH 5.0.1; serial IO used HDF5 1.14.6.

Commands used the tracked lockfile and cached dependencies. Common environment:

```sh
export QUEST_ROOT=/path/to/installed/quest
export MPICC=/path/to/mpich/bin/mpicc
export MPICH_CC=/usr/bin/gcc
export HDF5_DIR=/path/to/serial-hdf5-1.14.6
export CARGO_BUILD_JOBS=2
```

- Workspace build: `cargo build --workspace --all-features --all-targets --locked --offline`.
- Workspace Nextest: 558/558 passed; its three separate scale tests subsequently passed in release. Local MPI sockets were enabled for subprocess tests.
- Workspace doctests (46) and strict all-target/all-feature Clippy passed.
- Formatting, generator freshness, catalog freshness and package-content checks passed.
- Pure language/compiler/numerical builds passed with deliberately nonexistent QuEST and libclang selections; the production dependency graph excludes Astro Float and rsmpi.
- Direct, facade, wrapped and renamed downstream consumers built and ran outside Cargo with loader overrides removed and the complete native dependency closure resolved.
- A separately built non-MPI QuEST package ran a consumer successfully. With Cargo `mpi` enabled, references to `quest_sys::mpi` and `quest::collective` failed to compile because those APIs were configured out.
- The executable QSVT tutorial, numerical/offline tutorials, HDF5/native CLI tests and mdBook rendering passed. Final timing-scope refinements passed three focused trace regressions and the two-/four-rank lifecycle regression, followed by strict workspace Clippy.

Numerical data accompany this record under `data/2026-09-11-qsvt/`.

## Performance and reference scope

The [reproducible C++ comparison](../../benchmarks/reference/README.md) builds
public prepared-execution APIs from the pinned source with the same installed
QuEST target. The complex scalar degree-three fixture agrees with Rust to
`1.76e-16` in amplitude, `4.38e-19` in retained mass and `3.15e-16` in complex
Hadamard overlap; total Hadamard probability matches exactly. All four matrix
entries also match stored C++ canonical QSP fixtures through degree 8,105 and a
complex generalized fixture including its final K factor.

These are smoke timings on a shared host, not controlled throughput claims.
C++ repeated tiny-fixture execution measured about 51.39 microseconds versus
Rust 139.45 microseconds; Rust construction and preparation were faster in this
fixture. Sampling and public stage boundaries differ. The report preserves both
results without extrapolating to large states, GPU execution or multiple nodes.

| Canonical degree | C++ complete synthesis median (s) | Rust binary64 stages (s) | Rust Astro certification (s) | Rust combined (s) |
| --- | ---: | ---: | ---: | ---: |
| 9 | 0.06775 | 0.0000434 | 0.008813 | 0.008865 |
| 197 | 85.7342 | 0.0007727 | 0.50449 | 0.50533 |
| 1,581 | 15.3598 | 0.17027 | 7.06854 | 7.23944 |
| 8,105 | 33.4517 | 0.04010 | 43.84683 | 43.89236 |

C++ incorporates its own norm/enclosure machinery during synthesis. Its checked
contract and precision are not identical to Rust's separate all-entry Astro
certificate. These columns separate costs; they are not speedup ratios between
identical algorithms. Certification retries are included in cold-stage totals.

The explicit offline degree-8,105 Astro run measured 16.56 seconds of computation
plus 43.19 seconds of certification. The prior MPFR measurement was about 5.49
plus 20.03 seconds. Historical MPFR files are retained under clearly marked
names; they do not validate the replacement backend and the shared-host samples
are not a controlled backend benchmark.

## Limits of this evidence

No GPU execution, multiple-node MPI run, alternate MPI provider or 32-bit
execution was verified. GPU SDK loader closure was checked separately. Actual
mid-finalization MPI/GPU faults and insufficient-thread-support implementations
were not injected. Distributed solve, divergent SSA, and full-state gathering
remain outside the supported distributed profile.

Cargo dependency resolution precedes the native probe: explicitly selecting
the optional `mpi` feature builds rsmpi even when the native package makes the
MPI API disappear. Default production builds select neither dependency nor API.

Multiprecision storage/work budgets model algebraic storage and operations;
they are not hard caps on Astro's internal scratch or adaptive rounding work.
No production multiprecision allocator hook is exposed. RAII cannot clean up
an aborted process or deliberately forgotten owners. Timing JSON includes admission, optional trace writing and owner teardown in
its total, while final JSON printing remains outside it. The trace labels its
smaller post-admission scope `application_dispatch`. Empirical floating results
are not mathematical certificates.
