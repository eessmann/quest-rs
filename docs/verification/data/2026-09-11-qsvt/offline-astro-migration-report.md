# Explicit offline solver: Astro Float migration

The offline synthesis and approximation modules now use `astro_float::BigFloat` directly. No Rug compatibility layer, Rug import, native arbitrary-precision dependency, or production precision branch remains in these files. The workspace owner removed the old dependency. Public detailed values are `BigFloat`; `ApproximationFailure::mpfr_coefficients()` was replaced by `arbitrary_coefficients()`.

Every attempt owns a `Consts` cache. Precision and modeled storage are admitted before constructing the cache. Policies require whole backend words (default 128 bits, maximum 4096 bits), avoiding silent reporting of a 65-bit request that the backend actually computes at 128 bits. Arithmetic precision comes from the admitted configured precision or allocated mantissa capacity, never significant-bit count. Modeled scalar storage includes `size_of::<BigFloat>()` plus mantissa bytes; numerical work/byte budgets and retry accounting remain explicit. These resource estimates are not allocator hard caps on opaque backend internals.

All binary64 imports—including targets, expression constants, domains and tolerances—use the shared exact bit-decoding importer. This deliberately avoids the independently reproduced upstream `BigFloat::from_f64` subnormal-import defect. Binary64 exports use the shared exact dyadic rounding converter; nonfinite exports fail before certification. Offline arithmetic uses nearest-even rounding with represented dyadics treated as exact operands for subsequent rounded operations. Backend NaN/errors propagate to checked numerical boundaries and become typed `Precision` errors; constant-cache allocation errors are typed `Constants` errors. No unchecked NaN comparison can authorize acceptance.

FFT twiddles, Weiss completion, the ordered divide inverse, scaled controls, phase extraction and pivoted Householder QR now use Astro Float. Transcendental operations use the owned constant cache. Contractivity admission retains directed upper/lower arithmetic and the independent interval-circle FFT helper. Final exported binary64 candidates still require the separate independent certificate at the unchanged default 1e-11 tolerance. Remez exchange remains explicitly empirical; uniform error of its final binary64 polynomial is established using the original function AST's interval derivatives and subdivision.
