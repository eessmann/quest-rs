## Proposed narrow strategy, awaiting authorization

A process-wide RLIMIT_FSIZE cannot select only the stdout/stderr file descriptors; it also applies to MPI's internal shared-memory file extension. Preserve the4MiB stdout and4MiB stderr capture ceilings through a parent-owned pipe collector instead of applying that output limit as a global launched-process file limit. Read both pipes nonblocking through selectors in fixed≤64KiB chunks, checking each prospective retained length before writing to parent-owned capture files. Once either stream would exceed4MiB, retain only the allowed prefix, mark output-limit failure/truncation explicitly, kill the registered launcher process group, and reap the direct child. Continue bounded drain/discard until closure or a short cleanup deadline; preserve timeout and supervisor cleanup behavior. Never accumulate an unrestricted PIPE communicate buffer. Drain both streams together to avoid deadlock and process output even while checking timeout.
