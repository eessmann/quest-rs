# Independent allocation-contract resolution review

Reviewed the final clean `crates/quest-numerics/tests/warm_parallel.rs` and `ConvolutionWorkspace::convolve_with_policy` documentation. No actionable contract mismatch remains.

The test measures inside one caller-owned pool scope after four warmup calls. For one worker, it requires zero counted allocator calls across 1600 convolutions. A single worker cannot steal the second join child, so this avoids the contention-dependent join parking path structurally. For four workers, it runs 256 convolutions, checks the returned first complex coefficient against the independently computed input product `(0.0005, 0.0005)`, checks the expected length 1793, and checks that the returned output-buffer pointer stays unchanged. The four-worker allocation count is printed only; it has no asserted upper bound or zero-allocation guarantee. The value check covers the first coefficient of the final result, not every coefficient on every iteration.

Two distinct scheduler causes were diagnosed before correcting the test contract. External calls repeatedly submit through Rayon's segmented injection queue, whose Crossbeam blocks periodically allocate. The loaded in-pool trace then identified `std`'s macOS pthread condition-variable `OnceBox` initialization from `Rayon Sleep::sleep`, reached while waiting for a stolen FFT join child. A join/yield warmup cannot guarantee that every private worker parking path has occurred. The clean allocator no longer contains backtrace instrumentation, which temporarily disabled global tracking during trace capture and therefore could not establish a total diagnostic count.

The API documentation now explicitly says numerical work buffers are reused while external job-queue blocks and lazy OS synchronization storage may allocate, including after earlier calls. Neither this review nor the revised test claims that scheduler allocations are bounded or independent of call count. The four-worker pointer check establishes returned-buffer reuse; it does not by itself prove that all internal parallel work allocates nothing.

Verification evidence was inspected, without rerunning tests: `workspace-nextest-final.log` records this revised test passing and the final workspace summary of 885 passed, 6 skipped. This is local evidence for the stated test contract, not a portable scheduler allocation guarantee. Only this review file was written.
