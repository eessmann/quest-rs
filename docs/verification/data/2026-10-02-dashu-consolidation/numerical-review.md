# Independent numerical and architecture review

Scope: the Dashu consolidation in `quest-numerics`, `quest-qsp`, `quest-language`, `quest-symbolic`, `quest-math`, and `quest-synthesis`. Read the approved consolidation plan and the numerics, exact, and QSP owner reports. Compared relevant mathematical paths with `.superpowers/sdd/2026-10-02-rug-migration/source-before`; that snapshot predates the partial Rug migration, so it is used for algorithmic provenance rather than treating every diff as a Dashu change. Inspected published registry implementations for Dashu float 0.6.2, int 0.6.2, and ratio 0.6.1.

## Findings and verdict

**No actionable port-specific numerical correctness or architecture findings.** No P0–P3 defects identified in the reviewed paths. Spec and implementation-quality review pass for the numerical migration, conditional on the coordinator's final-tree validation and outstanding performance evidence. This review ran no builds or tests and makes no independent claim that the owner-reported tests pass on the final integrated tree. Source owners were still applying lint-only changes during review.

The native aliases, explicit rounding contexts, fallible arithmetic boundaries, independent verifier, canonical exact values, and deliberate wire encodings satisfy the intended design. I did not find a justified simplification that would improve these guarantees enough to require another implementation change. In particular, retaining a project-owned exact dyadic exporter is justified by its explicit IEEE boundary contract; replacing it with an unchecked native convenience conversion would weaken the design.

## Independently checked mathematical contracts

- **Directed operations and guard digits** (`quest-numerics/src/arithmetic.rs`, `binary_operation`, `unary_operation`; `quest-qsp/src/precision.rs`). Registry `round.rs` defines Down as toward negative infinity and Up as toward positive infinity. Registry `convert.rs::with_rounding` only replaces the type-level/context rounding mode and leaves the represented dyadic unchanged. Thus the `.value().with_rounding::<HalfEven>()` path preserves the already-directed result, including the allowed add/sub guard digit. No second rounding is inserted at interval endpoint transfer. Domain/range/Ziv failures propagate through the fallible context operations instead of becoming a successful bound.
- **Exact import and binary64 export** (`quest-numerics/src/arithmetic/interchange.rs`). Import reconstructs the hidden normal bit and the correct exponent, with a separate subnormal exponent of -1074. Export computes `top = bit_len(significand) + exponent`, chooses the exact binary64 quantum `max(top - 53, -1074)`, and rounds quotient/remainder with the correct parity and sign. The early tiny-value branch applies only strictly below half the least subnormal: at exactly `2^-1075`, `top == -1074`, so the halfway case still reaches ties-to-even. At the upper edge, `MAX + 2^969` remains below the overflow midpoint `MAX + 2^970`; the quotient/remainder path returns MAX for nearest and the proper directed neighbor. Carry into exponent 1025 causes overflow only after rounding. Subnormal carry into the minimum normal is encoded correctly. Signed zero is retained at the interchange boundary.
- **Decimal and ratio imports** (`quest-numerics/src/arithmetic.rs::parse`, `ratio`, `import`). Decimal digits are parsed as an exact signed integer, the decimal exponent is folded into an exact power-of-ten numerator/denominator, and a single selected binary division produces each endpoint. This avoids double rounding through a decimal float. Both ratio operands are admitted before cancellation, consistent with the stated resource policy. Native integer imports fit the minimum 64-bit precision. Precision selection is bit-granular, including 65 bits.
- **Interval arithmetic and trigonometric extrema** (`quest-numerics/src/arithmetic.rs::products`, `trig`, `integer_possible`). Multiplication/division enclose all four endpoint pairs with both directed operations, and zero-containing divisors fail. For sine, maxima satisfy `(x/pi - 1/2)/2` integral and minima satisfy `(x/pi + 1/2)/2` integral; for cosine, the corresponding phases are 0 and 1. The implemented outward interval quotients contain those exact values. Therefore integer exclusion is sound, while uncertain large reductions conservatively retain extrema. Endpoint trigonometric evaluations and retained extrema jointly enclose the complete input interval. Exact endpoint copying for hull/intersection/singleton avoids precision-change shrinkage.
- **Storage and exponent admission** (`quest-numerics/src/arithmetic.rs::validate_value`, `float_storage_bytes`, `working_scalar_bytes`; QSP context accounting). Exponent admission uses actual significand length and skips zero before inspecting its exponent. Registry IBig bit length is magnitude bit length, including for negative values. Native storage accounting counts actual words beyond the two-word inline representation; the working estimate admits one extra bit. QSP endpoint admission permits precision plus one digit, and its modeled scalar storage and retained constant-cache accounting include that distinction. These are logical stored-value models, explicitly not allocator-capacity or transcendental-scratch/process caps; the review does not upgrade them to those stronger guarantees.
- **Independent QSP verification** (`quest-qsp/src/certification/{interval,mod,product,projector}.rs`). The verifier retains its own complex rectangles, directed FFT/product reconstruction, complete four-entry matrix checks, and exact comparison of retained arbitrary-precision bounds with binary64 tolerances. Sharing primitive exact binary64 interchange does not merge it with candidate generation. In twiddle construction, exact axis cases are removed before reflection; the residual angle lies in `[0, pi/4]`, and the additional `[0,1]` numerical check establishes the monotonic domains used by sine/cosine endpoint evaluation. Reflection swaps sine/cosine, and quadrant sign permutations match `exp(i*2*pi*k/N)`.
- **Generation and retries** (`quest-qsp/src/offline/{number,kernels,mod}.rs`). Native arithmetic preserves configured precision for zero and real/complex construction. Original-input reconstruction on each attempt, explicit algorithm identity, inverse-NLFT default, complete exported controls/phases, bounded increasing precision, and cumulative work charging remain intact. Producer point arithmetic is followed by independent certification; its diagnostic residual is not substituted for a proof. Native arithmetic errors retain typed failure paths. The artifact precision checks no longer impose the obsolete word-alignment restriction.
- **Signed exact arithmetic and ring operations** (`quest-math/src/interval.rs`; `quest-synthesis/src/{grid,norm_equation}.rs`; `quest-math/src/ring.rs`). Registry IBig division truncates toward zero and remainder has the numerator's sign. Therefore the explicit `q - 1` correction exactly implements floor for negative nonintegral quotients with positive denominator; ceil via `-floor(-n/d)` is correct. For example, `-7/3` becomes floor -3 and ceil -2, whereas `-6/3` remains -2 at both ends. Registry signed right shift rounds toward negative infinity, preserving the old negative midpoint behavior. Negative parity bit zero agrees with parity modulo 2, and coefficient shifts during ring normalization apply only to even coefficients. Norm-equation modular powers use nonnegative seeds and positive moduli; field-norm denominators are positive for nonzero ring elements. The radial excess comparison explicitly uses `> RBig::ZERO`, avoiding Dashu's non-strict positive-sign classification of zero.
- **Canonical rational identity and serialization** (`quest-language/src/rational.rs`, `quest-math/src/encoding.rs`, exact angle construction and symbolic affine values). `RBig::from_parts_signed` reduces and moves denominator sign to the numerator. Native unsigned denominators preserve positive canonical identity. Wire parsers compare canonical decimal spelling, reject zero/negative denominators and unreduced pairs, and AngleTarget output normalizes local signed pairs. Integer coefficient arrays deliberately serialize as decimal strings. Rational-to-binary64 conversion still uses exact quotient/remainder and one final rounding, and mathematical-pi/affine conversion retains its separate rational interval refinement and cap.
