# quest-cfd implementation and acceptance record

This working-tree delivery provides a full-coordinate nonlinear BDM1 smoke
solve and reusable sparse/matching/QSVT runtime infrastructure. It does not
close every requirement in the research plan. In particular, coarse classical
snapshots are not published benchmark reproductions, and single-host MPI does
not establish multi-host capacity.

## Implemented paths

* Validated numerical CSR/CSC with deterministic duplicate summation, sparse
  adjoints/products/norm bounds and compatibility through `quest-qsvt-io`.
* Compact fixed-bit/range spaces and coherent projector operations.
* Owned matching encodings, complex rotations, reversible completion, bounded
  forward/adjoint gate replay, arithmetic tensor shifts and weighted stencils.
* Reciprocal synthesis/certification with physical scaling and residual checks;
  compact QSVT schedules for the scalar and native matching backends.
* Owned matching shards, native checked local/indexed amplitude transfers,
  prepared CPU/MPI unitary execution with bounded reusable routing buffers.
* Complete BDM1/P0 charts on triangular/tetrahedral meshes, stationary boundary
  lifting, central convection and SIP viscosity; full pressure/momentum checks.
* Central configuration DG1/DG2 half-density transport and causal global
  temporal DG1/DG2 assembly without normal equations. The built-in solve uses
  the proved DG1 singular-value enclosure.
* `reference`, `build`, `solve` and `estimate` workflows, case manifests,
  arbitrary-width exact/symbolic dimensions and explicit resource rejection.

See the [derivation](../research/quest-cfd-derivation.md),
[crate guide](../../crates/quest-cfd/README.md) and
[physical foundation](../../crates/quest-cfd/foundation.md).

## Reproducible commands

Select an installed QuEST built with matching MPI and subcommunicator support.
Use the same MPI implementation for QuEST, `MPICC` and `mpiexec`.

```sh
export QUEST_ROOT=/path/to/installed/quest
export MPICC=/path/to/matching/mpicc
export CARGO_INCREMENTAL=0
export CARGO_BUILD_JOBS=2
export CARGO_PROFILE_DEV_DEBUG=0
export CARGO_PROFILE_TEST_DEBUG=0
cargo nextest run --workspace --all-features --no-fail-fast
cargo test --workspace --all-features --doc
cargo clippy --workspace --all-features --all-targets --no-deps -- -D warnings
cargo fmt --all --check
cargo run --locked -p xtask -- generate-quest-bindings --check
cargo build --release -p quest-cfd
python3 docs/verification/fixtures/quest-cfd/run.py \
  target/release/quest-cfd /tmp/quest-cfd-cases.json
cargo run --release -p quest-cfd --features quantum -- \
  solve --case smoke --backend quest-cpu
```

MPI integration tests launch actual timeout-bounded MPI child processes. Sandboxed
systems must permit local MPI sockets. The local native consumer uses runtime
library paths discovered from the installed QuEST package.

## Nonlinear circuit experiment

The smoke case has 12 local velocity coefficients, constraint rank 7 and all 5
independent coordinates. Two DG1 cells on every configuration axis give 1,024
coefficients. The generator has 5,482 nonzeros; one causal DG1 slab produces a
2,048-dimensional history with 15,060 nonzeros. The global horizon is 0.01,
configuration extent is [-1,1] per axis, and initial regularization width is 1.2.
The drift has independently verified nonzero quadratic coupling and inviscid
energy cancellation.

The scalar and native QuEST CPU executions use the identical complete unitary,
17 qubits, degree 401, alpha 8 and certified projector phases. A measured
residual is execution evidence; neither its small size nor the polynomial
certificate proves physical convergence. On this two-cell grid all cells are
boundary cells. Independent width/domain/configuration/physical/temporal
refinements remain necessary.

[smoke.json](data/2026-10-04-quest-cfd/smoke.json) records the full construction,
certification, physical scaling, success mass, measured residual and stage
timings. The relative history residual is about `5.25993e-6` on both backends;
success probability is about `0.00794757`. These are classical simulations of a
quantum circuit, not quantum-hardware results. Single-run timings were collected
concurrently and do not support a comparative speedup claim. Peak RSS includes
the native linked libraries and is separate from modeled allocation admission.

## Repository and MPI acceptance

[acceptance.json](data/2026-10-04-quest-cfd/acceptance.json) records the final
checks: 1,237 all-feature workspace tests passed, with three existing scale tests
skipped; 65 documentation tests passed, with one ignored. Strict all-feature,
all-target workspace Clippy, formatting, binding freshness and whitespace checks
passed. Release builds with and without native execution passed. The existing
nightly `generic_const_exprs`/next-solver compatibility warning remains.

Actual matching tests passed on 1/2/4/8 ranks and on four ranks split into two
independent communicators. They exercise complex arbitrary whole-register
states, both flag sectors, dummy colors, inactive signed controls, permutations,
adjoints, source corruption and local-memory admission. The full QSVT schedule
also passed a two-rank cross-partition differential. A native buffer-error
injection after execution began terminated the blocked peer via MPI abort within
a 20-second timeout. This does not establish every transport/allocation failure
mode.

[mpi.json](data/2026-10-04-quest-cfd/mpi.json) records maximum-rank timings and
communication volumes for a 512-amplitude diagnostic. The eight-rank adjoint
query sent/received 29,568 application bytes in total, with a per-rank maximum of
6,096 bytes. Each batch is bounded by 64 pairs/128 records. Counts exclude MPI
protocol overhead and separate collective/native traffic. See the
[distributed contract](../research/distributed-matching.md) for ownership,
admission, failure and scaling limits.

Integration testing caught and corrected padded MPI overlap preparation and
unequal-volume pressure-gauge regressions. Review additionally corrected source
payload binding, remaining-budget propagation, temporal mass underflow and
spectral-proof overflow handling. Binding generation now formats Rust output
with the repository configuration before freshness comparison; generated
signatures remain unchanged.

## Classical and capacity receipts

[cases.json](data/2026-10-04-quest-cfd/cases.json) contains executable arguments,
exit statuses, JSON reports, elapsed time and peak RSS from `/usr/bin/time`.
The fixture performs two RK4 steps of 0.0001 on coarse full BDM1 meshes. Eight
configurations execute across five physical families. The ninth, the approved
Re300 3D stationary wake, is explicitly rejected because its Neumann far-field
and convective-outflow operator is not implemented. All nine configurations
receive untruncated resource estimates.

The pure Rust estimator is also run with a 256 MiB address-space cap. For a
100-by-100-by-100 periodic tetrahedral mesh it retains 30,000,001 independent
coordinates and reports the exact expression `4^30000001 * 20` for the history
dimension. With the explicit 16-ancilla allowance this needs 60,000,023 qubits.
The allowance is not an encoding-specific resource proof. Decimal expansion is
rejected when its metadata exceeds the configured bound; the exact expression
remains available. Separate small construction/work budgets produce explicit
nonzero rejection exits.

This cap test concerns symbolic accounting. It does not execute an exponential
state or demonstrate distributed sparse input larger than one node's memory.

## Open requirements

* Higher physical BDM orders, scalable physical constraint elimination and
  time-dependent boundary lifting.
* The complete paper-specific structured base/PREP/UNPREP implementation and
  distributed sparse matching preprocessing/loading. Current `from_encoding`
  is a bounded reference convenience; production shard callers must supply
  their own distributed source preparation.
* Approved 3D wake boundary execution and all published-window benchmark
  campaigns, including force/Strouhal statistics and independent geometry
  refinement. Short snapshots are not steady/periodic reference solutions.
* Full nonlinear KvN convergence across independent regularization, domain,
  configuration, physical mesh and temporal refinements, and rigorous
  oracle/execution/sampling error budgets for physical observables.
* Performance work on distributed scheduling: batches currently scan common
  global indices and use O(P) peer rounds. No multi-host scalability claim.
* Forced allocator/rank-loss tests, genuinely large-count jobs and actual
  multi-host capacity runs with the source larger than every node's cap.
* Accelerator execution for the new fused path; admission currently rejects it.

No commit, merge or push is part of this delivery.
