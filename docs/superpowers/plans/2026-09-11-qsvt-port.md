## Global constraints

- Production Remez, FFT, Weiss, NLFT, numerical lowering, preparation and
  repeated QuEST execution use binary64. No automatic multiprecision fallback.
- arbitrary-precision is confined to separate certification, independent references and an
  explicitly selected offline solver. Verification checks a fixed binary64
  export; increased verifier precision cannot repair that export.
- Preserve faer with explicit Par::Seq, strong types, owned immutable stages,
  exact versus numerical semantics, register borrowing and RAII-only cleanup.
- No security attestation or hostile-input framework. Validate mathematical
  domains, dimensions, allocations, effects and MPI ordering for correctness.
- All crates remain beneath crates/, inherit metadata/lints/dependencies,
  and use the pinned nightly and tracked workspace lockfile.
- Source baseline: quest-qsvt develop 7fe7f740579b03c52a8cf48be6a31268b029c19f.
  Rust baseline: main cb77d2c43ed0265c11f22a26aa1dca9c536ba88e.
- Correctness references are the supplied versioned papers, independent
  numerical fixtures, and the source's documented conventions. Source quirks
  that violate those contracts are not compatibility requirements.

## Crates and boundaries

quest-numerics owns binary64 kernels, intervals, policies and workspaces;
quest-polynomial owns typed bases and mathematical expressions; quest-qsp
owns completion, inverse NLFT, controls and certification; quest-qsvt owns
pure encodings and transforms; quest-qsvt-io owns HDF5/JSON; quest-qsvt-cli
owns application workflows. Runtime integration is in quest under qsvt.
No pure crate depends on quest or quest-sys.

Use RustFFT 6.4.1, maryada 0.2.1 without linear algebra, optional Rayon
1.12.0, and optional astro-float 0.9.6 (std only) for certification/offline computation.
HDF5 uses hdf5-metno with serial root-only IO. Use cargo-edit for additions.
Keep candidate, certification and explicit offline entrypoints distinct.
Response tolerance defaults to 1e-11, separately from approximation error.
Verifier precision starts at 256 bits; explicit offline starts at 128 bits.
Both have caller budgets; offline defaults to a maximum of 4096 bits.

## Task 1: M12 numerical and circuit foundations

Implement checked binary64 policies, planned FFT/convolution buffers and
reusable shared circuit fragments. Degree/dimensions stay runtime values;
type markers carry basis, parity, conventions and capabilities.
Every shared invocation remains a distinct ordered occurrence.
Add Rust oracle captures evaluated once, explicit numerical adjoint, and
preserve exact-only inverse/negative powers. Language owns signatures/IDs;
circuit owns captured payloads. No staged projection-to-oracle conversion.
Test independent complex convolutions, budgets, remapping, global phase,
capture count, exact/numerical capability and unsupported QASM export.

## Task 2: M13 polynomials and function expressions

Implement monomial, Chebyshev, Laurent, Hermite, Laguerre and Jacobi bases,
support offsets, conversion bounds, parity, derivative/domain evaluation,
critical-point isolation and binary64 Remez. One function expression drives
scalar, interval and derivative evaluation. Separate callbacks carry an
explicit consistency assumption. Test endpoint, complex, support,
conversion, derivative, root and approximation behavior.

## Task 3: M14 production QSP and independent certification

Implement strict contractivity, Weiss completion, forward scattering and
divide-and-conquer inverse NLFT. First-half inversion precedes midpoint
update and second-half inversion. Export tagged canonical phases and
generalized controls, with direct scaled reflection normalization, complete
scalar phase, multiplication order and final K convention.
Reconstruct actual binary64 exports independently; preserve all four
matrix-polynomial entries. Separate response/completion/conversion/unitary
defect. Failed sufficient bounds mean tolerance not established.

## Task 4: M15 scaling, parallelism and explicit offline solver

Keep direct interval convolution as the reference. Add balanced product-tree
verification with outward arbitrary-precision FFT convolution, exact support, enclosed
twiddles and inverse normalization. Precision retries verify the SAME export.
Offline arbitrary-precision recomputes from original inputs, with its own FFT, completion,
inverse and pivoted-QR Remez kernels; production never calls it implicitly.
Use caller-owned Rayon pools, deterministic reductions/error selection and
reused per-worker scratch. Account work and memory including precision.
Exercise every catalog family through degree 8105, recording configured
tolerances, production success, explicit offline success and unavailable
bounds separately. No blanket 1e-12 catalog promise.

## Task 5: M16 encodings, transforms and prepared runtime

Implement rectangular projected encodings, left/right spaces, normalization,
coordinate/isometry/dense projectors and exact-vs-numerical residual evidence.
Port standard Wx symmetric/Laurent QSVT, direct Hermitian GQSVT, structural
hermitianization and reduced-even/reduced-odd multiplication.
Preserve fixed admissions, degree-zero readout and oracle counts.
Execution order: input projection, main, bridge projection, continuation,
output projection. Odd multiplication retains its final source continuation.
Postselection result exclusively borrows the register; condition/release
consume it. Keep absolute mass, subnormalized states and failure prefixes.
Prepare native data once; no arbitrary-precision in preparation or execution.
Prepared transforms are state-vector only; coherent circuits retain density
support. Unsupported generalized theorem robustness stays uncertified.

## Task 6: M17 applications, IO, catalog and tutorials

Provide synthesize, catalog, solve, embedded and overlap workflows, explicit
offline selection, HDF5/JSON compatibility, deterministic sparse densification
and all 21 inverse families. Port generation/checking into xtask.
Solve is square/full-rank and uses A-adjoint; preserve physical scaling and
separate normalized-state output. Catalog labels alone do not prove error.
Hadamard reports preserve complex overlap and absolute retained mass.
Add executable mdBook/rustdoc guidance and CLI/file migration documentation.

## Task 7: M18 MPI, profiling and integrated acceptance

User override: use official rsmpi (Cargo package mpi 0.8.2). Own its Universe
and SimpleCommunicator values inside MpiRuntime and borrowed communicator
wrappers, requiring MPI_THREAD_MULTIPLE on every rank. Keep only the minimal
C++ QuEST lifecycle/handoff and fatal cleanup support. Select rsmpi with an
explicit MPICC and verify its compiled ABI and actual MPI library identity
against the selected QuEST::QuEST target before initialization/handoff.
Gate rsmpi behind an optional quest-sys mpi feature so pure compilation and
ordinary native consumption do not gain mpi-sys/bindgen/libclang dependencies.
Also gate the public MPI API, CXX handoff and tests on the selected native
package's MPI+SUBCOMM capability, using checked quest_native_mpi cfg emitted
by quest-build. A non-MPI package hides the API and skips compatibility probes;
Cargo features still select optional dependencies before build scripts run.
Prefer admitted-communicator builders and ownership states over boolean APIs.
Ownership: MPI runtime -> communicator -> collective environment -> resources.
Use initCustomMpiCommQuESTEnv; QuEST frees its duplicate without finalizing
caller-owned MPI. QuEST native admission remains once per process.
General application split may exclude ranks or use arbitrary sizes; admit
power-of-two subgroup sizes before QuEST entry. Threaded borrowed application views
cannot finalize/free. Collectives have exclusive ordered lanes and separate
contexts. QuEST remains thread-confined; do not serialize blocking application
MPI through its lifecycle mutex.
Subgroup root synthesizes with local workers and broadcasts frozen results.
Agree preparation and execution schedules; return ordinary preflight errors
consistently and abort the job on unrecoverable collective/cleanup failures.
Use shared private RuntimeResources and a read-only EnvironmentView for both
owner kinds; expose no conversion to the ordinary local owner. Collective
prepare compares complete canonical semantic payload bytes, including exact
complex values, ordered targets, signed controls, phases and recursive oracles;
never attest plans with Debug strings or hashes. Split pure admission/reservation
from shared native materialization, and identify prepared/register instances in
collective execution preflight. Bound root-only amplitude input storage; expose
scalar norm/probability and unnormalized projector operations for postselection.
Keep local retirement policy. Distributed support covers embedded/Hadamard,
not solve, full-state gather/output or divergent SSA.

Use typed no-op observers and synchronous Perfetto/Chrome trace export.
Measure approximation, synthesis, certification (including retries), offline
computation, construction/lowering, preparation, warm execution,
postselection and total cost separately. Do not hide certification cost.
